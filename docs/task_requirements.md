- `evaluated_leaves`：实际调用终止状态评价逻辑的次数。
- `cutoff_events`：触发 Alpha-Beta 剪枝条件的次数。
- `pruned_siblings`：由于剪枝而跳过的同层剩余子分支数量。
- `runtime_ms`：搜索执行时间。

# 第二部分：题目一——迷宫寻路

## 3. 问题定义

在一个二维网格中，通过 A* 算法寻找起点 S 到终点 E 的最短路径。

地图元素：

- `S`：起点。
- `E`：终点。
- `.`：可以通行的格子。
- `X`：障碍物，不可通行。

仅允许上下左右四方向移动。

每次移动代价为 1。

返回从起点到终点的完整最短路径坐标序列；如果不可达，返回空列表。

## 3.1 函数接口

必须提供以下公开接口：

```python
def solve_maze(
    start: tuple[int, int],
    goal: tuple[int, int],
    grid: list[list[str]]
) -> list[tuple[int, int]]:
    ...
```

要求：

- 返回路径包含起点和终点。
- 如果存在多条等长最优路径，返回其中任意一条。
- 无解返回 `[]`。
- 不修改调用方传入的地图。
- 支持任意有效矩形网格。

内部建议构建通用搜索核心：

```python
def astar_search(
    start: Coord,
    goal: Coord,
    shape: tuple[int, int],
    is_blocked: Callable[[Coord], bool],
    enter_cost: Callable[[Coord], float],
    heuristic: Callable[[Coord, Coord], float],
    *,
    stats: AStarStats | None = None
) -> PathResult:
    ...
```

题目一和题目二需要复用此核心，而不是复制两份 A* 实现。

## 3.2 数学定义

定义状态：

`s = (row, col)`

合法动作：

`A(s) = {up, down, left, right}`

状态转移：

`s' = (row + dr, col + dc)`

其中 `s'` 必须在地图范围内，且不能是障碍物。

边代价：

`c(s, s') = 1`

累计代价：

`g(start) = 0`

`g(s') = g(s) + 1`

启发函数采用曼哈顿距离：

`h(s) = |row_s - row_goal| + |col_s - col_goal|`

A* 评价函数：

`f(s) = g(s) + h(s)`

需要在报告中解释：在四方向、单位边权的条件下，曼哈顿距离为什么是可采纳且一致的启发函数。

## 3.3 算法实现要求

使用 `heapq` 维护开放列表。

必须实现：

1. 对起点进行初始化。
2. 根据 `f` 值取出优先级最高的候选节点。
3. 跳过已经失效的旧队列条目。
4. 检查目标条件。
5. 枚举合法后继。
6. 当发现更优的 `g` 值时，更新 `g_score` 和 `came_from`。
7. 找到目标后，利用 `came_from` 反向恢复完整路径。
8. 如果队列耗尽仍未到达目标，返回无解。

需要使用稳定、可复现的 tie-breaking 策略。

例如，对 `f` 相同的节点，使用确定性的次级排序和递增序号。记录所选择的策略，并在所有对照实验中固定。

不要将一个节点第一次被发现的代价直接视为其最终最优代价。

应设计能够处理更优路径更新的逻辑。

## 3.4 课程样例

输入：

注意：不应强制要求返回完全相同的坐标路径，只需要验证路径合法、连续、起终点正确且长度最优。

## 3.5 必须覆盖的边界测试

- 非法输入：抛出 `ValueError` 并提供明确的信息。

## 3.6 正确性测试

在单位代价网格下，BFS 求得的最短路径长度应当与 A* 一致。

对于每一个随机测试地图，需要验证：

建议实验变量：

# 第三部分：题目二——加权地形

## 4. 问题定义

将迷宫扩展为具有非均匀移动成本的网格。

地图格子可以具有不同地形代价，例如 1、3、8。

移动规则仍然是四方向。

从 A 移动到相邻格子 B 时，边代价等于进入 B 的地形权值。

课程样例还明确规定：

**进入终点 E 的最后一步代价为 0。**

这是一条必须特殊处理的规则。

## 4.1 函数接口

```python
def solve_weighted_terrain(
    start: tuple[int, int],
    goal: tuple[int, int],
    grid: list[list[int | str]]
) -> int:
    ...
```

要求：

- 返回起点到终点的最小移动总代价。
- 不可达返回 `-1`。
- 课程样例应返回 `7`。
- 内部应能恢复最优路径，供分析和测试使用。
- 公共接口只返回总代价，以满足题目格式。
- 继续复用题目一的通用 A* 核心。

可以支持 `X` 障碍物作为合理扩展，但必须在规格文档中说明这不是题目二样例的额外要求。

## 4.2 数学定义

令 `w(v)` 为格子 `v` 的进入成本。

在本题中：

- 普通数字格子的进入成本为相应非负数。
- `S` 的起始成本不计入初始累计成本。
- `E` 的进入成本为 0。
- `X` 如果存在，则不可进入。

状态转移成本：

`c(u, v) = w(v)`

其中终点满足：

`w(E) = 0`

路径总成本：

`Cost(P) = sum(c(p_i, p_(i+1)))`

起点初始成本：

`g(start) = 0`

## 4.3 启发函数设计

必须严肃处理终点 E 的零代价。

普通曼哈顿距离：

`h(n) = Manhattan(n, E)`

在此问题下不一定可采纳。

例如，当前节点与终点相邻时，实际剩余代价是 0，但普通曼哈顿距离是 1。

因此不能直接套用题目一的公式并宣称最优性得到保证。

要求实现两个安全的基准版本：

**版本一：零启发式**

`h_0(n) = 0`

**版本二：修正的曼哈顿启发式**

若所有非终点可通行格子的进入成本至少为 `w_min > 0`，则可以使用：

`h_adjusted(n) = max(Manhattan(n, E) - 1, 0) * w_min`

课程给定的地形最小成本为 1，因此可简化为：

`h_adjusted(n) = max(Manhattan(n, E) - 1, 0)`

对于存在零成本普通地形、或无法保证上述权值条件的扩展输入，应使用安全下界（例如 `h=0`），而不是错误地沿用正权下界。

报告中需要说明：

- 为什么减去 1。
- 为什么该启发式不会高估剩余成本。
- 在规定的权值条件下，它是否满足一致性。
- 启发式可采纳性与 A* 实际实现正确性之间的关系。

## 4.4 课程样例

```python

goal = (4, 4)

grid = [
    ['S', 1, 1, 8, 1],
    [1, 8, 3, 1, 1],
    [1, 8, 1, 8, 1],
    [1, 1, 1, 8, 1],
    [8, 8, 1, 1, 'E']
]
```

课程期望输出：

```python

```

课程提供的其中一条最优路径：

```python

    (1, 0),
    (2, 0),
    (3, 0),
    (3, 1),
    (3, 2),
    (4, 2),
    (4, 3),
    (4, 4)
]
```

沿路径进入七个普通代价为 1 的格子，再进入免费终点 E，因此总代价为 7。

必须通过这一样例。

## 4.5 边界条件

至少测试：

- 起点与终点相同。
- 终点紧邻起点，总代价应为 0。
- 存在多条同代价最优路径。

- 输入中起点、终点坐标与地图标识不一致。

## 4.6 正确性验证

独立实现 Dijkstra 算法作为参考。

对于大量随机加权地图，验证：

`AStarOptimalCost == DijkstraOptimalCost`

此外检查：

- 恢复路径的成本重新计算后是否等于算法返回值。
- 是否正确使用目标格子的进入成本。
- 是否错误计入了起点成本。
- 是否错误地为终点 E 收费。
- 无解情形的返回值是否正确。

## 4.7 对照实验

至少比较：

1. Dijkstra / `h=0`。
2. 修正曼哈顿启发式。

实验变量可包括：

- 地图规模。

# 第四部分：题目三——Minimax 与 Alpha-Beta 剪枝

## 5. 问题定义

实现极大极小博弈树搜索。

根节点为 MAX 玩家。

MAX 和 MIN 在不同深度交替行动：

- MAX 节点选择最大子节点值。
- MIN 节点选择最小子节点值。
- 叶节点提供固定评价值。

课程要求默认从左到右访问子节点。

## 5.1 数据结构与函数接口

课程定义：

```python
class TreeNode:
    def __init__(self, value=None, children=None):
        self.value = value
        self.children = (
            children if children is not None else []
        )
```

应兼容此结构。

建议提供：

```python
def minimax(
    root: TreeNode,
    maximizing: bool = True,
    *,
    stats: GameStats | None = None
) -> int | float:
```


- `original` 保持原始子节点顺序。
- 可额外支持 `reverse` 和可复现的启发式访问顺序。
- 不改变输入树。
- 不修改叶节点值。
- 支持负数、零以及一般数值叶节点。

## 5.2 Minimax 数学定义

设 `V(n)` 为节点 n 的 Minimax 值：

如果 n 是叶节点：

`V(n) = value(n)`

如果 n 是 MAX 节点：

`V(n) = max(V(child) for child in children(n))`

如果 n 是 MIN 节点：

`V(n) = min(V(child) for child in children(n))`

要求实现完整递归，不使用任何剪枝，作为 Alpha-Beta 的独立正确性基准。

## 5.3 Alpha-Beta 数学定义

维护两个边界：

- `alpha`：MAX 已知的最好下界。
- `beta`：MIN 已知的最好上界。

初始值：

`alpha = -infinity`

`beta = +infinity`

MAX 节点：

1. 初始化 `best = -infinity`。
2. 递归访问子节点。
3. 更新 `best = max(best, child_value)`。
4. 更新 `alpha = max(alpha, best)`。
5. 如果 `alpha >= beta`，剪掉尚未访问的剩余子节点。

MIN 节点：

1. 初始化 `best = +infinity`。
2. 递归访问子节点。
3. 更新 `best = min(best, child_value)`。
4. 更新 `beta = min(beta, best)`。
5. 如果 `alpha >= beta`，剪掉剩余子节点。

要求正确传递边界，并解释剪枝为何不影响根节点的最优值。

## 5.4 课程样例

构建如下节点：

```python

leaf2 = TreeNode(value=5)
leaf3 = TreeNode(value=6)
leaf4 = TreeNode(value=9)
```

# 第五部分：题目四——A* 与 Alpha-Beta 综合博弈

## 6. 问题定义

这是整个实验的核心综合任务。

两名玩家：

- A：MAX。
- B：MIN。

四个宝藏：

| 宝藏 | 位置 | 价值 |
|---|---|---:|
| T1 | (0, 6) | 9 |
| T2 | (2, 2) | 6 |
| T3 | (4, 4) | 7 |
| T4 | (6, 0) | 7 |

玩家初始位置：

- A：`(0, 0)`
- B：`(6, 6)`

完整地图为：

```python
grid = [
    ['A', 1, 1, 'X', 2, 1, 'T1'],
    [1, 'X', 6, 'X', 1, 'X', 1],
    [1, 1, 'T2', 1, 1, 1, 1],
    ['X', 1, 'X', 8, 'X', 1, 'X'],
    [1, 1, 1, 1, 'T3', 1, 1],
    [1, 'X', 9, 'X', 1, 'X', 1],
    ['T4', 1, 1, 'X', 1, 1, 'B']
]
```

所有地图坐标使用 `(row, col)`。

移动规则：

- 上下左右移动。
- `X` 是不可通行的障碍物。
- 数字表示进入格子的代价。
- A、B、T1、T2、T3、T4 所在格子的进入成本全部为 1。
- 两名玩家互不阻挡。
- 经过其他宝藏不会自动获得。
- 已被获取的宝藏所在格子仍然可以通行。

行动顺序：

`A -> B -> A -> B`

每回合当前玩家选择一个尚未被获得的宝藏，并移动至该宝藏位置。

注意：行动是“选择并获取一个宝藏”，不是在地图上移动一步。

四个决策构成完整博弈。

## 6.1 路径成本预计算

必须首先使用 A* 计算以下六个关键节点之间的最小移动代价：

`A, B, T1, T2, T3, T4`

输出 6×6 距离矩阵。

建议接口：

```python
def compute_distance_matrix(
    grid: list[list[int | str]],
    labels: tuple[str, ...] = (
        "A", "B", "T1", "T2", "T3", "T4"
    )
) -> dict[str, dict[str, float]]:
    ...
```

对于本题给定地图，独立验算得到的参考矩阵为：

| From / To | A | B | T1 | T2 | T3 | T4 |
|---|---:|---:|---:|---:|---:|---:|
| A | 0 | 12 | 10 | 4 | 8 | 8 |
| B | 12 | 0 | 8 | 8 | 4 | 10 |
| T1 | 10 | 8 | 0 | 6 | 6 | 12 |
| T2 | 4 | 8 | 6 | 0 | 6 | 6 |
| T3 | 8 | 4 | 6 | 6 | 0 | 6 |
| T4 | 8 | 10 | 12 | 6 | 6 | 0 |

这个矩阵是基于课程地图和进入成本规则独立计算的回归测试参考值，不是课程 PDF 直接提供的数值表。

必须由算法计算得到，不允许硬编码返回此矩阵。

由于本题六个关键位置的进入代价均为 1，距离矩阵表现为对称形式。

但从更一般的数学角度看，“进入目标格子收费”的代价模型可能产生方向相关的路径代价。

因此，通用实现不能无条件假设 `d(u, v) == d(v, u)`。

## 6.2 博弈收益定义

设宝藏 `Ti` 的价值为 `Vi`。

设玩家当前位置为 `p`。

通过预计算距离矩阵查询最小移动代价：

`d(p, Ti)`

单次获取宝藏的收益定义为：

`Gain(p, Ti) = Vi - d(p, Ti)`

双方累计得分分别为：

`Score_A`

`Score_B`

博弈效用：

`U = Score_A - Score_B`

MAX 玩家 A 希望最大化 U。

MIN 玩家 B 希望最小化 U。

特别注意：

- 单次 Gain 可以为负数。
- 不允许将负收益截断为 0。
- 不能只比较宝藏价值而忽略移动成本。
- 不能让玩家在一个回合中获得多个宝藏。
- 不能把玩家移动途中经过的其他宝藏自动加入收益。

## 6.3 状态建模

建议使用不可变数据结构：

```python
@dataclass(frozen=True)
class TreasureState:
    pos_a: str
    pos_b: str
    remaining: frozenset[str]
    score_a: int
    score_b: int
    current_player: str
```

状态至少包含：

1. A 的当前位置。
2. B 的当前位置。
3. 尚未被获取的宝藏集合。
4. A 的累计收益。
5. B 的累计收益。
6. 当前行动玩家。

可增加深度、历史动作序列等辅助信息，但必须明确哪些属于搜索状态，哪些只用于结果追踪。

初始状态：

```python
TreasureState(
    pos_a="A",
    pos_b="B",
    remaining=frozenset({
        "T1", "T2", "T3", "T4"

    score_a=0,
    score_b=0,

```

## 6.4 状态转移函数

建议接口：

```python

    state: TreasureState

    ...
```

```python

    state: TreasureState,
    target: str,
    distance_matrix: dict,
    treasure_values: dict[str, int]

    ...
```

假设当前玩家为 A，选择 Ti。

首先计算：

`gain = Vi - d(pos_a, Ti)`

状态转移：

```text
pos_a' = Ti
pos_b' = pos_b

remaining' = remaining - {Ti}

score_a' = score_a + gain
score_b' = score_b

current_player' = B
```

若当前玩家为 B：

```text

pos_b' = Ti

remaining' = remaining - {Ti}

score_a' = score_a
score_b' = score_b + gain

current_player' = A
```

每次状态转移都应生成新状态，不得通过共享可变对象破坏其他搜索分支。

对于扩展场景下的不可达宝藏，应明确行动合法性策略。建议仅允许当前玩家选择可到达的剩余宝藏；若无合法动作，则将当前状态作为终止状态，并在规格中记录此约定。

课程固定地图中的宝藏均可到达。

## 6.5 搜索深度定义

搜索深度 `H` 表示从当前根状态向前搜索多少次宝藏选择。

例如：

- `H=2`：A 选择一次，B 选择一次，然后评价。
- `H=4`：执行完整的 A→B→A→B 四次宝藏选择，然后评价。

终止条件：

- 达到给定的搜索深度。
- 所有宝藏已经被获取。
- 没有合法动作可选。

终止评价：

`Eval(state) = score_a - score_b`

必须严格使用这一课程规定的效用，不得在基础实现中擅自加入额外的未来收益估计。

深度大于剩余宝藏数量时，应在宝藏耗尽后正常终止。

内部搜索允许 `H=0` 用于评价当前状态；如果公共求解接口需要返回首步，此时 `best_target` 应为 `None`。

## 6.6 Minimax 求解

建议提供：

```python
def treasure_minimax(
    state: TreasureState,
    depth: int,
    distance_matrix: dict,
    treasure_values: dict[str, int],
    *,
    stats: GameStats | None = None
) -> int | float:
    ...
```

规则：

- A 行动时枚举全部合法宝藏，取子状态评价的最大值。
- B 行动时枚举全部合法宝藏，取子状态评价的最小值。
- 到达终止条件时返回当前收益差。

必须能够恢复 A 在根状态应选择的最优第一个宝藏。

不要只返回数值而丢失根动作。

对于不同动作具有相同最优收益的情况，定义稳定的 tie-breaking 规则，例如使用 `T1, T2, T3, T4` 的固定顺序选择最先出现的最优动作。

## 7. 控制变量原则

所有性能对照必须遵循：

**一次主要只改变一个因素。**

例如：

研究启发函数时：

- 固定地图。
- 固定起点终点。
- 固定邻居访问顺序。
- 固定硬件与软件环境。
- 仅改变启发函数。

研究 Alpha-Beta 访问顺序时：

- 固定博弈树。
- 固定搜索深度。
- 固定评价函数。
- 仅改变子节点访问顺序。

不要同时改变多个关键条件后直接归因。

## 7.1 随机实验规范

随机测试使用固定种子。

需要记录：

- 种子。
- 地图尺寸或博弈树结构。
- 数据生成参数。
- 使用的算法。
- 配置参数。
- 原始统计结果。

建议使用多次独立实例重复实验，而非只挑选表现最好的样例。

## 7.2 时间测量

对于执行时间较短的算法：

- 先执行必要的预热。

# 第七部分：创新与拓展研究

## 8. 创新要求

基础题全部正确之后，至少完成一项具有数据证据的算法优化，以及一项自设拓展实验。

不要求发明新算法，但要求能够：

- 解释改进思想。
- 明确适用条件。
- 保证正确性。
- 设计公平对照。
- 提供实际数据。
- 讨论额外开销与局限。

## 8.1 优先研究：Alpha-Beta 节点排序

研究问题：

**节点访问顺序对 Alpha-Beta 的剪枝效率有多大影响？**

至少设置：

- 原始顺序。
- 反向顺序。
- 启发式顺序。

对于综合题，可以尝试基于即时收益构造低开销排序：

- MAX 倾向于优先搜索可能获得较大效用的动作。
- MIN 倾向于优先搜索可能降低效用的动作。

这里的即时收益排序只是搜索顺序启发式，不能替换原本的 Minimax 评价函数。

必须验证：

1. 排序前后根节点的最优值是否一致。
2. 扩展节点数是否变化。
3. 叶节点评估次数是否减少。
4. 剪枝次数和跳过分支数如何变化。
5. 排序自身耗时是否抵消了剪枝带来的收益。

## 8.2 可选研究：缓存与重复状态

可以研究：

- 路径距离缓存。
- 重复博弈状态。
- 状态价值缓存。
- 预计算与在线计算之间的成本权衡。

如果对 Alpha-Beta 引入 Transposition Table，必须区分：

- EXACT：精确值。
- LOWER_BOUND：下界。
- UPPER_BOUND：上界。

不能把所有发生剪枝后返回的值都直接视为精确 Minimax 值。

缓存键需要包含决定未来决策的全部必要状态和剩余深度；如果缓存的是未来增量效用，需要正确处理当前累计收益的平移。

如果无法充分保证缓存正确性，优先不启用该优化，而应保留正确的基础实现。

## 8.3 可选研究：搜索规模与理论复杂度

通过不同深度和分支因子的合成树，研究 Minimax 与 Alpha-Beta 的搜索开销增长。

分析：

- Minimax 的指数级搜索空间。
- Alpha-Beta 的最佳、平均和最坏情况差异。
- 访问顺序对实际复杂度的影响。
- 理论复杂度与有限规模实验之间的关系。

注意不要根据少量数据宣称证明了普遍的渐近复杂度结论。
